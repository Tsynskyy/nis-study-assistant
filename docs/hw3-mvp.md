# ДЗ 3. Проверка подходов, MVP и оценка качества

## MVP

Код - каталог `assistant/`, запуск - `python3 -m assistant ask "..."`
Примеры (дата "сегодня" 06.10.2026):

```text
> Какие ближайшие дедлайны?
Ближайшие дедлайны:
- 2026-10-09 23:59 - Задание 1. Загрузка отчетной документации + Проверка на Антиплагиат (Курсовой проект)
- 2026-10-09 23:59 - Домашнее задание №2. Основы Kubernetes (SRE 2026-2027)
- 2026-10-10 23:59 - Задание 2. Загрузите сюда отчет из антиплагиата (Курсовой проект)
  [deadlines; источники: deadline#21, tbank#31, deadline#22]

> Сколько баллов можно набрать по БКС?
По сообщениям курса от 15 и 22 сентября за семестр можно получить 105 баллов: ...
  [rag; источники: AUTUMN-2026.md#14 ...]

> Какой рецепт борща?
Не нашел ответа в учебных материалах.
```

Задержка поиска во всех вариантах меньше 1 мс (p95 <= 0,5 мс), то есть цель < 2 с выполняется с огромным запасом; построение индекса при старте - доли секунды

Подбор длины префикса для стемминга (BM25 + маршрутизатор): 4 буквы - hit@3 0,917, но точность отказов падает до 0,75 (слишком много случайных совпадений); 6 букв - hit@3 0,875; выбрано 5

## Что изменилось по ходу проверки

1. **Первая версия маршрутизатора ухудшала качество** Любой вопрос со словами "срок", "сдать" уходил в инструмент дедлайнов LMS
   Вопрос "Срок ДЗ №2 по Kubernetes в SRE?" получал список дедлайнов курсового проекта, потому что SRE в выгрузке LMS нет
   С маршрутизатором hit@3 BM25 было 0,833 против 0,875 без него
   Исправление: общий список дедлайнов выдается, только если вопрос не про конкретный курс из сводок; если курс найден в дедлайнах, они фильтруются по нему
2. **Добавлен второй источник дедлайнов** - задания Т-Образования
   После этого вопрос про Kubernetes отвечается точной датой из кабинета курса

## Выбор

BM25 + маршрутизатор: лучшее hit@3 (0,917) и доля верных ответов, все отказы верные
Цели ДЗ 1 (hit@3 >= 0,8, отказы >= 0,75) выполнены

## Ограничения оценки

- Набор маленький (28 вопросов) и составлен автором системы - оценка оптимистичная
- Проверялась выдача нужного фрагмента, а не формулировка ответа
  Генерация локальной моделью в этой оценке не измерялась; тесты проверяют вызов Ollama и откат на извлечение, если модель недоступна
- Оставшиеся промахи - перефразы: "итоговая оценка" против "Итог - 60 %", "дедлайн онлайн-тестов", когда нужный фрагмент на 5-м месте
