# ДЗ 5. Имитация эксплуатации и мониторинг

## Как имитировалась эксплуатация

В `eval/traffic.txt` записаны 32 вопроса, как я их задал бы в обычной жизни: разговорные формулировки, сокращения ("ОРГ", "БКС"), 4 вопроса не по теме
Они не пересекаются с размеченным набором из ДЗ 3
Каждый прогнан через `python3 -m assistant ask` (BM25 + маршрутизатор, "сегодня" 06.10.2026); все запросы записаны в журнал `logs/queries.jsonl`
Затем каждый ответ размечен вручную (`eval/traffic_labels.csv`: верен ли первый источник)

## Мониторинг

`python3 -m assistant report` считает по журналу:

- число запросов по дням;
- распределение маршрутов: инструмент дедлайнов, RAG, отказ;
- долю отказов и вопросы без ответа (кандидаты на пополнение данных);
- задержку p50/p95;
- самые используемые источники;
- возраст данных по времени последнего обновления;
- алерты при выходе за цели ДЗ 1

Отчет по имитации:

| Метрика | Значение | Цель | Статус |
| --- | --- | --- | --- |
| Запросов | 32 | - | |
| Маршруты | RAG 26, дедлайны 3, отказ 3 | - | |
| Доля отказов | 9,4 % | <= 20 % | норма |
| Задержка p95 | 0,6 мс | < 2 с | норма |
| Возраст данных | 2,8 дня | <= 7 дней | норма |
| **Верный первый источник (ручная разметка)** | **17 из 32 = 53 %** | - | **ниже ожиданий** |

Технические метрики в норме, но качество на живых вопросах заметно ниже, чем на размеченном наборе (hit@1 0,667, hit@3 0,917)
Значит, размеченный набор из ДЗ 3 слишком похож на формулировки в сводках, и оценка была оптимистичной

## Что делать по итогам

1. **Пополнять размеченный набор из журнала** Все 32 вопроса с разметкой добавить в eval: тогда оценка будет отражать реальные формулировки
2. **Маршрутизатор:** вопрос о сроках без названия курса ("на этой неделе") всегда отправлять в инструмент дедлайнов, даже если RAG что-то нашел
3. **Словарь сокращений** (ОРГ, БКС, НИС, ФОРС, КР) - разворачивать в запросе
   Сделано, см. ниже
4. **Гибридный поиск:** добавить эмбеддинги (например, multilingual-e5-small) к BM25, чтобы находить перефразы
   Ожидаемый эффект - основная часть из 7 ошибок перефраза
5. **Генерация LLM по топ-3** вместо показа одного фрагмента: в части ошибок нужный фрагмент есть на 2-3-м месте
6. **Порог отказа** проверить на вопросах не по теме из журнала: "погода в москве" прошла порог из-за одного совпавшего слова

## Доработки по итогам эксплуатации

1. **Словарь сокращений** Запрос дополняется расшифровкой сокращения, если в данных используется только полное название
   Проверка показала, что это нужно только для ОРГ: БКС и ФОРС встречаются в сводках как есть, и их расшифровка размывала запрос (hit@1 падал с 0,667 до 0,625, "мягкий дедлайн БКС" уходил к экзамену ОРГ)
   В словаре оставлено одно сокращение
2. **Склейка основ** Префикс в 5 букв давал разные основы для "итог" и "итоговая", "оценивание" и "оценка"; добавлена таблица одинаковых основ
3. **Стоп-слова вопроса** "Считается" - редкое слово в данных, поэтому оно получало большой вес и уводило вопрос "как считается итоговая оценка по SRE" к курсовому проекту

| Вариант | hit@1 | hit@3 | MRR | верных ответов | верных отказов |
| --- | --- | --- | --- | --- | --- |
| BM25 + маршрутизатор, до | 0,667 | 0,917 | 0,778 | 0,917 | 1,0 |
| BM25 + маршрутизатор, после | 0,667 | **0,958** | 0,792 | **0,958** | 1,0 |

Формула оценки SRE теперь в топ-3 (на первом месте по-прежнему раздел про 3-й модуль), поэтому LLM получает нужный фрагмент
На вопросах из эксплуатации верных первых источников 18 из 32: исправился "сколько длится экзамен ОРГ", остальные не изменились

## Генерация на локальной модели

Ассистент работает только на локальной модели через Ollama
Прогон 06.10.2026 на домашнем ПК: Ollama 0.35.1, модель gemma4:e4b, видеокарта RTX 4070 Ti 12 ГБ

Первый прогон нашел ошибку: gemma4 перед ответом рассуждает и тратила на это весь лимит в 500 токенов, Ollama возвращала пустой текст, а ассистент считал его ответом
Исправление: лимит 2000 токенов (`LLM_MAX_TOKENS`), пустой ответ модели считается сбоем, и ассистент отвечает без генерации
Добавлен тест

| Вопрос | Без LLM | gemma4 до исправления | gemma4 после |
| --- | --- | --- | --- |
| Ближайшие дедлайны | 3 из 3 | 2 из 3 | 2 из 3 |
| Сколько баллов по БКС | верно | пустой ответ | верно, 105 баллов |
| Что сдать на пересдачу НИС | фрагмент без прямого ответа | пустой ответ | по сути верно |
| Как считается оценка по SRE | не тот фрагмент | "во фрагментах нет" | "во фрагментах нет" |
| Рецепт борща | отказ | отказ | отказ |

Выдуманных фактов не было: если нужного фрагмента нет, модель так и говорит
Модель иногда теряет пункты из списка (третий дедлайн), поэтому для дедлайнов надежнее ответ инструмента без генерации
Прогон с gemma4 был до доработки поиска; ответ про оценку SRE после нее на модели не перепроверялся

Мониторинг по прогону: доля ответов LLM 0,56, отказов 0,19, задержка p95 12,6 с - сработал алерт (цель < 2 с)
Первый запрос 38 с (загрузка модели), дальше 7-13 с
Для ежедневного использования это приемлемо, но цель по задержке из ДЗ 1 с локальной моделью на таком ПК не выполняется; варианты - модель меньше или генерация только для вопросов, где поиск не уверен

Мониторинг продолжает работать на реальных запросах: еженедельно смотреть отчет, вопросы без ответа и долю отказов; при алерте о возрасте данных запускать обновление парсера
